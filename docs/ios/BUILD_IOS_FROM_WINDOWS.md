# Building GoStudy for iPhone from a Windows laptop

No Mac, no local Xcode. You edit and sync on Windows; a macOS runner in GitHub
Actions compiles the app, and you install the result from Windows.

---

## 1. What this project actually is (inspection summary)

| Layer | Detail |
|---|---|
| Web app | React 18 + TypeScript SPA, Vite 8 (`dist/` is the build output), React Router 6, Tailwind/Radix UI, framer-motion |
| Native shell | **Capacitor 8.6.2** — `@capacitor/core`, `/cli`, `/ios`, `/android` all on the same version |
| WebView plugins | `app`, `browser`, `filesystem`, `haptics`, `local-notifications`, `preferences`, `screen-orientation`, `share`, `splash-screen`, `status-bar`, `device`, `file-opener` (all 8.x, `>=8.0.0` peer-compatible) |
| Backend | Supabase (`@supabase/supabase-js` 2.x) for auth/DB, Cloudflare R2 (`catalog/*.json` + PDFs) for library content |
| Android packaging | `com.gostudy.student`, versionCode 15 / versionName 1.3.3, AGP 8.13.0, Gradle 8.14.3, compileSdk/targetSdk 36, minSdk 24, release-signed with `android/app/scoretarget-release-key.jks` |
| iOS packaging | `ios/App/App.xcodeproj`, Swift Package Manager (no CocoaPods), bundle `com.gostudy.student`, 1.3.3 (build 15), iOS 15+ |

Android and iOS share the same web bundle, the same Supabase project and the
same R2 catalogue — only the native container differs.

## 2. Approach

1. **Wrap, don't rewrite.** Capacitor serves the existing Vite `dist/` inside a
   `WKWebView`. UI, navigation, assets, Supabase auth and R2 reads are untouched.
2. **Swift Package Manager, not CocoaPods.** Capacitor 8 generates
   `ios/App/CapApp-SPM/Package.swift`, which references the plugins from
   `node_modules`. No `pod install`, no Ruby, nothing to install on Windows.
3. **Windows produces the project, macOS produces the binary.** Everything that
   needs a compiler (Swift, asset catalogs, code signing) happens on the runner.
4. **Fix the two Windows-specific traps** (both automated by
   `npm run ios:prepare`):
   - `cap sync` on Windows writes Windows paths (`..\..\..\node_modules\...`)
     into `CapApp-SPM/Package.swift`; SwiftPM on macOS treats `\` as a literal
     character and fails to resolve the packages. The script rewrites them to
     `/`.
   - Capacitor 8 requires **iOS 15**, but the template ships `13.0`. The script
     raises `IPHONEOS_DEPLOYMENT_TARGET` and the SwiftPM platform to 15.
5. **Do not touch Gradle.** iOS is built by `xcodebuild` only.

## 3. Windows prerequisites

- **Node.js 22 LTS** (Vite 8 needs `^20.19.0 || >=22.12.0`) — `node -v`
- **Git**
- A GitHub repository (the project already points at
  `github.com/Mira-x77/grade-goal`)
- Optional for installing the result: **Sideloadly** or **AltStore** on Windows

Nothing else. No Xcode, no macOS, no Ruby, no CocoaPods.

## 5. Exact commands (Windows)

```powershell
# one-time / after pulling changes
npm ci --legacy-peer-deps

# build the web bundle, copy it into the iOS project, fix SPM paths + iOS target
npm run ios:sync

# verify only (no build) — prints every check it performs
npm run ios:prepare
```

`npm ci --legacy-peer-deps` is required: `lovable-tagger` declares
`vite <8`, while the project runs Vite 8. Without the flag npm aborts with
`ERESOLVE`. This is unrelated to iOS.

`npm run ios:sync` is three steps:

```powershell
npm run build                    # dist/
npx cap sync ios                 # dist/ -> ios/App/App/public, plugins -> CapApp-SPM
node scripts/ios/prepare-ios.mjs # POSIX paths + iOS 15 deployment target
```

Commit the result (`ios/App/App.xcodeproj`, `ios/App/App/Info.plist`,
`ios/App/CapApp-SPM/Package.swift`) and push.

## 6. Cloud build — unsigned IPA (free Apple ID)

1. **Settings → Secrets and variables → Actions** → add:

   | Secret | Value |
   |---|---|
   | `VITE_SUPABASE_PROJECT_ID` | `aaayzhvqgqptgqaxxbdh` |
   | `VITE_SUPABASE_URL` | `https://aaayzhvqgqptgqaxxbdh.supabase.co` |
   | `VITE_SUPABASE_ANON_KEY` | the anon key from your `.env` |
   | `VITE_CATALOG_URL` | *optional*, defaults to the R2 catalogue |

   `.env` is gitignored, so CI rebuilds it from these values. Missing secrets
   fail the job with a clear message instead of shipping a broken bundle.

2. **Actions → iOS build (unsigned IPA) → Run workflow** (or push a tag
   `ios-v1.3.3`).
3. Download the `gostudy-ios-unsigned-ipa` artifact when the job finishes.
4. Install from Windows:
   - **Sideloadly** → connect iPhone → drag the `.ipa` → enter your Apple ID →
     Start. The app is re-signed with a development certificate.
   - **AltStore** does the same and refreshes the signature automatically over
     Wi-Fi.
   - Free Apple IDs: the signature expires after **7 days** and must be renewed.
     A paid account removes that limit and enables TestFlight.

An unsigned `.ipa` cannot be installed by tapping it — iOS verifies the
signature chain. That is an Apple platform rule, not a project limitation.

## 7. Cloud build — signed IPA (paid Apple Developer, $99/year)

Prepare on Windows:

```powershell
# 1. Create a Certificate Signing Request and an "Apple Distribution" cert in
#    developer.apple.com -> Certificates. Download cert.cer, then export it from
#    Keychain Access as cert.p12 (you need a Mac for the p12 export step), or use
#    a service such as Codemagic's certificate manager.

# 2. Register the App ID com.gostudy.student (developer.apple.com -> Identifiers).

# 3. Create an App Store provisioning profile for that App ID, download the
#    .mobileprovision.

# 4. Base64-encode both files for GitHub Secrets (PowerShell):
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.p12"))        | Set-Clipboard
[Convert]::ToBase64String([IO.File]::ReadAllBytes("GoStudy.mobileprovision")) | Set-Clipboard
```

Add these secrets: `IOS_TEAM_ID`, `IOS_DIST_CERT_P12`, `IOS_DIST_CERT_PASSWORD`,
`IOS_PROFILE_SPECIFIER` (the profile's exact name), `IOS_PROVISIONING_PROFILE`.

Then run **Actions → iOS release (signed IPA)** and pick the export method
(`app-store-connect`, `ad-hoc`, `development`, `enterprise`). The workflow
archives, exports and uploads `GoStudy-1.3.3-15.ipa` as an artifact.

Optional one-click upload to App Store Connect — add `ASC_KEY_ID`,
`ASC_ISSUER_ID`, `ASC_PRIVATE_KEY` (base64 of `AuthKey_XXXXXXXXXX.p8`) and the
last step runs `xcrun altool --upload-app`. Without them, upload the `.ipa`
with the **Transporter** app (free, macOS/Windows store) or Xcode.

### Equivalent commands on a borrowed Mac

```bash
npm ci --legacy-peer-deps
npm run ios:sync
cd ios/App

# unsigned device build (what CI does)
xcodebuild build -project App.xcodeproj -scheme App -configuration Release \
  -sdk iphoneos -derivedDataPath ../../DerivedData \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO

# signed archive + export
xcodebuild archive -project App.xcodeproj -scheme App -configuration Release \
  -destination 'generic/platform=iOS' -archivePath ../GoStudy.xcarchive \
  DEVELOPMENT_TEAM=<TEAM_ID> CODE_SIGN_STYLE=Manual \
  PROVISIONING_PROFILE_SPECIFIER="<profile name>"

xcodebuild -exportArchive -archivePath ../GoStudy.xcarchive \
  -exportOptionsPlist ../ExportOptions.plist -exportPath ../export
```

Or simply `npx cap open ios`, pick your team in **Signing & Capabilities**, then
**Product → Archive → Distribute App**.

## 8. App Store submission checklist

- [ ] Apple Developer Program membership active
- [ ] App ID `com.gostudy.student` registered (capabilities: Push if you plan to
      enable notifications; nothing else is required today)
- [ ] App record created in App Store Connect with the same bundle ID
- [ ] Screenshots: 6.9" (iPhone 16 Pro Max) and 6.5" required; 5.5" only if you
      support older devices — the app is iPhone+iPad (`TARGETED_DEVICE_FAMILY = 1,2`)
- [ ] Description, keywords, support URL, privacy policy URL (`https://gostudy.app/privacy`)
- [ ] Age rating questionnaire, category (Education)
- [ ] **App Privacy** answers: the app talks to Supabase (auth + usage) and R2
      (content). Declare e-mail/identifier collection if accounts are created
- [ ] Export compliance: already answered in `Info.plist`
      (`ITSAppUsesNonExemptEncryption = false` — HTTPS only)
- [ ] TestFlight build installed and smoke-tested on a real device
- [ ] Review notes: demo account for the library, and a line explaining that PDFs
      are hosted on Cloudflare R2

Existing placeholders to review before submission: `Info.plist` declares
`UIBackgroundModes = remote-notification` although no push plugin is installed
(App Review may ask why), and `UISupportsDocumentBrowser = true`. Both are
harmless for sideloading/TestFlight; tighten them for a public release.

## 9. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `npm ci` → `ERESOLVE could not resolve` | Pre-existing Vite 8 / `lovable-tagger` conflict. Use `npm ci --legacy-peer-deps`. |
| `xcodebuild: error: Cannot find package ... node_modules\@capacitor\...` | `CapApp-SPM/Package.swift` still has Windows separators. Run `npm run ios:prepare` (or `npm run ios:sync`). |
| `building for iOS 13.0, but linking in object file built for iOS 15.0` | Deployment target not raised. Run `npm run ios:prepare`. |
| `Signing for "App" requires a development team` | Expected for signed builds; the unsigned workflow sets `CODE_SIGNING_ALLOWED=NO`. |
| App shows a blank screen on device | Web assets missing: make sure `cap sync ios` ran after `npm run build`, and that `.env` existed at build time. |
| `Missing Supabase environment variables` at runtime | The bundle was built without `.env`. In CI, add the three `VITE_SUPABASE_*` secrets. |
| Library empty but papers load on Android | Check `VITE_CATALOG_URL` is baked in; verify `https://pub-91f336347bd944c48d724d28d0d3b647.r2.dev/catalog/papers.json` returns 200 from the phone's network. |
| Free-Apple-ID app stops opening after a week | Normal — 7-day provisioning. Re-install through Sideloadly/AltStore, or use TestFlight. |

## 10. What is still manual (and why)

- **Producing the binary**: needs macOS. A macOS GitHub runner is free for
  public repositories and metered for private ones (2,000 min/month on the free
  plan; an iOS build takes ~6–10 minutes).
- **Signing**: needs an Apple identity. Free = 7-day sideload; paid = TestFlight
  and App Store.
- **Device verification**: the iOS app has not been run on hardware yet — the
  project is configured and CI-ready, but the first install has to happen on your
  iPhone (see `pending/08-ios-app.md`).
